# UI spec

## Global

- Left/right sidebar flips with direction (RTL: sidebar on the right). Language toggle in header, persisted.
- Use CSS logical properties; mirror directional icons (arrows, chevrons); don't mirror clocks/logos.
- Numerals: Western digits by default (setting for Arabic-Indic). Dates: show Gregorian; weekday names localized. Week starts Saturday option (setting; Egypt default Saturday).
- Every string is an i18n key `area.screen.element`. No hard-coded text.
- States for every screen: loading, empty, error, permission denied.
- Destructive/approval actions use confirm dialogs with a required reason where audit demands it.
- Cairo is the only UI typeface. Body copy is at least 15px/500, labels and buttons use 700, and headings use 700–800. Payroll-v2 spacing, borders, surfaces, semantic status colours, and contrast tokens are reused everywhere.
- Desktop layouts reflow at reduced window widths: cards wrap, multi-column forms collapse, navigation becomes compact, and data tables scroll inside their cards instead of forcing the whole window wider.

## Screens

1. **First-run setup**: language, create admin (username, password with strength meter), backup folder, timezone (default Africa/Cairo).
2. **Login / lock**.
3. **Home (Import)**: a quiet operational view containing only today's shifts, the attendance-file import action, and three or four plain KPI numbers. Do not show sparklines, helper paragraphs, carousel indicators, or a "real data" note.
4. **Import wizard**: steps in IMPORT_FORMATS. Shows malformed lines, duplicate count, and coverage confirmation. A labelled five-row raw-punch sample explains that shown IDs come from the device file and are not necessarily unknown users. Known employee IDs import immediately even when unknown IDs exist. Unknown IDs open one resolution dialog and never render as a long inline punch list. The dialog heading, table heading, and confirmation footer remain visible while its body scrolls.
5. **Unknown device IDs**: group unmatched punches into one row per device ID with punch count and first/last punch date. The dialog supports searching/selecting an employee for each ID, "Ignore for now", and audited "Ignore permanently". Re-import is idempotent and permanently ignored IDs stay excluded.
6. **Employees**: list with photo, name, device ID, status; add/edit drawer; salary fields visible to admin only. Permanent removal is a separate danger action available only after deactivation, a reason, and exact device-ID confirmation; its confirmation explains every related record that will be removed.
7. **Shifts**: templates table with an easy relative-window editor. Fields are shift name, start, end (with explicit "+1 day" when overnight), late grace in minutes, check-in opening in minutes before start, check-in closing time, check-out opening in minutes before end, and overtime cap in minutes. Check-out remains open until the overtime cap; it is not described as having a separate close time. A live summary shows the scheduled shift, check-in window, check-out window, grace threshold, and maximum overtime using localized day labels. Reject negative values, invalid or zero-length shifts, windows outside their allowed bounds, and any open-ended OUT cap that overlaps the same employee's next IN window.
8. **Schedule**: month calendar per employee and team grid; chips: shift name, REST, COVERAGE, LEAVE, OVERRIDE, COVERAGE NEEDED (red). Click a day → override dialog (reason). Pair manager. Weekly rest editor.
9. **Monthly attendance**: employee + month selector. A compact summary bar above the table shows employee name, month, days present, days absent, total accepted worked time, total late time, and total overtime. Tabs switch between the daily attendance table and an overtime-only table for the selected employee-month. Daily columns, in order, are date, shift, actual IN, actual OUT, worked hours/minutes, late, early leave, overtime, result, and actions. Always show actual IN/OUT when present. Correction actions use short localized text labels (Correct IN, Correct OUT, Adjust day) so their purpose is visible without interpreting icons. Corrected days show an "Edited" badge whose tooltip contains the correction reason. The daily table owns its vertical scrolling region so its header, date column, and actions column remain visible while scrolling. Status badges use colour plus localized text, never colour alone. Row detail shows raw punches, matching, corrections, ignored/debounced punches, and audit history. A complete accepted pair is shown as present immediately; the waiting label explicitly says the shift is still open and is waiting for checkout/import.
10. **Corrections / Leave**: dialogs with reason (required).
11. **Payroll preview v2** (admin, service-enforced): header with employee, month, Recalculate, and Change month rules controls; selecting an employee or month immediately loads the preview. A KPI strip shows present days, confirmed absences, total late minutes, and total overtime minutes. The main area contains a table-owned scrolling region plus a 390px sticky summary on wide screens. The day table columns are date, localized status badge, shift (including a visible Coverage badge when applicable), actual IN, actual OUT, late minutes, deduction, overtime minutes, bonus, day methods, and net adjustment. There is no edit icon or second day editor. Long status text wraps inside the status cell and never overlaps the shift cell. The lateness and overtime selectors use separate semantic labels with a directional cue to their respective control. Deduction choices are Follow month rule, None, Minutes, Hours, Full day, and Custom amount. Bonus choices are Follow month rule, None, Per hour, As work days, and Custom amount. Both default to Follow month rule and recompute the row and sticky summary immediately. Custom amount reveals an inline amount field and required reason; other explicit overrides reveal an optional note. Rest and confirmed-absence rows are grey and inert; absence is priced only on the separate absence line. Status, late, overtime, deduction, and bonus use the shared semantic colour tokens. The table header remains visible inside its scrolling region. The summary states the number of charged late dates and displays the active formula; full-day rules are explained as charged dates multiplied by daily wage so the hourly price is not mistaken as active.

    **Month-rules drawer:** a 620px drawer opens from the right in RTL and the left in LTR while a modal scrim dims the payroll screen. Edits update the visible table and summary live before saving. Section 1 contains shared prices: late-hour price H, hour threshold T, short-lateness amount S, full-day threshold X, read-only daily wage, overtime-hour price R, minimum overtime minutes M, rounding, and overtime hours per extra day K. Section 2 selects the default lateness method and section 3 selects the default overtime method. Per-day methods never own prices. The footer shows “N days follow the rule, N edited manually”, a scope selector (this employee or all employees for the month), Save, Reset edited days, and Cancel. Cancel restores the saved configuration and preview; Reset edited days returns all date selectors to Follow month rule. The sticky summary shows editable base salary, late deduction, absence deduction, overtime bonus, prominent final salary, Approve, and Print.
12. **Advanced payroll compatibility**: legacy policies remain readable in the engine and approval history. The normal workflow presents the v2 month rules and per-date overrides rather than exposing raw legacy identifiers.
13. **Users & permissions** (admin): create users, grant/revoke admin (cannot remove last admin).
14. **Audit log** (admin): filter by date/user/entity; verify-chain button. A separate danger-zone reset requires a reason and typed confirmation, states that the operation is irreversible, and begins a new audit chain with a reset marker.
15. **Backup & restore** (admin): create, list, verify, restore with warnings; last backup date.
16. **Settings**: language, numerals, week start, lockout, idle lock.

## UX quality bar

- Month table usable at 1366×768 and 1920×1080; sticky header, sticky date/actions columns, and keyboard navigation.
- Print/export-friendly month report (ATT-7) in both languages.
- Errors show human message + code; never raw stack traces.
- Base body typography is one step larger than the original prototype. Headings and form labels use stronger weights. Text/background token combinations must meet WCAG AA contrast in both light surfaces and the dark navigation, including disabled, secondary, warning, and selected states.
